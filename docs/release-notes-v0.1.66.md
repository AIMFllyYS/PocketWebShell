# PocketWebShell 0.1.66

制作应用、网站图标与强制刷新的整套修复，并整合分类浏览数据清理。上一份 GitHub Release 是 0.1.65，本说明只覆盖 0.1.66。

## 制作应用

- 浏览菜单里的「制作应用」现在对普通 HTTP(S) 网页可用：进入预填好地址与标题的编辑页，保存后成为常驻桌面的应用。
- 空白页与内部资源页保持限制；本地 HTML 文件继续走原有的文件持久化流程，不进入网页应用流程。
- SPA 的地址变化会同步到当前网页草稿；晚到的自动图标可以补进尚未填写图标的草稿。

## 网站图标

- 接通 WebView 原生 `onReceivedIcon` 回调，并补充渲染后的图标声明采集与限时采集，覆盖只在脚本运行后才出现图标的站点。
- SVG 图标走专用解码，支持受限大小的内嵌图片；候选按实际可解码结果依次回退，覆盖 200 返回 HTML 的假 favicon。
- 自动图标以内容摘要命名的 PNG 保存在私有目录，更新时生成新的显示引用，避免图片缓存旧图。
- 显式设置的自定义图标及其备份来源受到保护；修复图标与历史写入的时序问题，以及跨来源登录图标覆盖、历史清理后旧加载回填。

## 主页强制刷新

- 主页「强制刷新」现在真的会重新加载网页资源，而不只是重新抓取元数据。
- 有存活会话时直接加载并绕过缓存；没有存活会话时记录请求，下次打开该应用时绕缓存。
- 整个导航保持绕缓存策略，在完成、错误、取消与超时后恢复默认；Cookie 与网站业务存储默认保留。

## 浏览数据清理

- 存储管理新增分类清理：缓存、Cookie、网站数据、历史可以分开处理，使用 Android 平台公开的缓存与数据清理 API，不再直接删除 Chromium 私有目录。
- 网站详情新增同源离线资源重置：使用不执行网站脚本的最小同源文档，等待并检查 CacheStorage 与 Service Worker 注册结果。
- 清理与补充采集串行执行；旧内核上部分删除不会被当成完整成功。

## 已知边界

- Android WebView 没有受支持的公开 DNS 缓存清空接口，本次没有宣称清理系统 / 内核 / 上游 DNS；`clearCache(true)` 是共享资源缓存操作。
- HTTP 强刷不能保证绕过网站离线脚本，服务器或 CDN 也可能返回旧内容。
- 离线资源重置会保留 Cookie、LocalStorage 与 IndexedDB，但网站放在 CacheStorage / Service Worker 里尚未同步的内容可能丢失。
