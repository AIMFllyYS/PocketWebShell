# 校园开源说明

本文给在校同学、第一次来仓库的贡献者，以及想基于玄览做课程作业或社团项目的人。法律效果以根目录 [LICENSE](../LICENSE) 为准；本文只解释我们为什么这样选、你怎么参与。

## 1. 项目是什么

PocketWebShell（应用内名称「玄览」）是 Kotlin / Jetpack Compose 写的 Android 应用：把网站做成主屏入口，用系统 WebView 打开。它是 **1037Solo 生态**的挂载项目，源码在：

https://github.com/AIMFllyYS/PocketWebShell

官网（静态站，无账号后端）：https://xuanlan.1037solo.com

当前公开测试版本线保持 **0.1.x**。正式包只出现在 GitHub Releases，不经过维护者自建的更新服务器。

## 2. 为什么用 GPL-3.0-or-later

我们需要一种**带 copyleft 约束**的许可：别人拿这份项目去改、再把改过的应用分发给用户时，也必须把对应源码以同样条件公开，而不能改完就变成闭源产品。

对照常见选择：

| 许可 | 再分发改过的应用时 | 为什么没选 |
|---|---|---|
| Apache-2.0 / MIT（0.1.63 及更早） | 可以闭源 | 不满足「改完分发仍须开源」 |
| MPL-2.0 | 只约束改过的文件 | 包一层新壳即可闭源 |
| LGPL-3.0 | 主要约束库的链接方式 | 玄览是**应用**，不是给别人链的库 |
| AGPL-3.0 | 网络提供服务也视为要公开源码 | 玄览是装在手机上的客户端，不是网站后台；AGPL 会明显劝退校园和企业贡献者，收益很小 |
| **GPL-3.0-or-later** | 分发衍生作品必须按 GPL 提供对应源码 | **当前选择** |

GPL **不会**要求你：

- 只在自己手机里用、或课程作业只给老师看，就必须把作业公开（没有「分发」就没有这项义务）；
- 向作者汇报你在用；
- 禁止商业使用。

GPL **会**要求你：在把修改版 APK 或源码公开发给他人时，附上许可、说明改动，并提供 Corresponding Source（能从源码构建出你分发的那个二进制）。本仓库已经用 Gradle Wrapper，构建步骤见 [README.md](../README.md)。

「or-later」表示接收方可以按 GPL 第 3 版，或自由软件基金会日后发布的后续版本使用。许可正文本身仍是 GPL 第 3 版，放在 `LICENSE`。

与 Android 依赖的关系：Jetpack、OkHttp、Coil 等 Apache-2.0 / MIT 组件可以进入 GPL-3 应用；组合成品再分发时按 GPL-3。系统 WebView 是操作系统组件，不把整台 Android 变成 GPL 作品。

## 3. 和历史版本的关系

0.1.63 及更早的 GitHub Release 是在 **Apache-2.0** 下发布的。从 **0.1.64** 起改为 GPL-3.0-or-later。旧包不会被「改写成一直是 GPL」。新的贡献按仓库当前许可授权。

若你 fork 的是旧 tag，请看那个 tag 里的 `LICENSE`。

## 4. 欢迎怎样贡献

完整流程在 [CONTRIBUTING.md](../CONTRIBUTING.md)。这里是校园场景里最有用的几条：

1. 从 `dev` 拉分支，不要直接改 `main`。
2. 先读 [AGENTS.md](../AGENTS.md) 里你要动的那一块不变量（主屏几何、WebView 会话归属、签名材料不进仓库）。
3. 一次 PR 只做一件事；用 Conventional Commits。
4. 提交即表示你有权、并愿意按 `GPL-3.0-or-later` 授权（inbound = outbound）。建议 `git commit -s` 加上 DCO 签名。
5. **不要**公开贴漏洞利用。安全问题走 [SECURITY.md](../SECURITY.md)。
6. 不要提交 APK、密钥、本机路径、`.env` 或 debug 包。

适合上手的方向：文档与文案、单元测试、无障碍、设置页文案、站点兼容性的可复现报告（附日志时先去掉 Cookie 和完整 URL 查询串）。

大改主屏手势或 WebView 内核前，请先开 Issue 对齐，避免和 launcher / 会话不变量打架。

我们**不使用** CLA（不要求转让版权、也不为了以后改成闭源去收授权）。保持轻量，是为了让同学把时间花在代码和设计上。

## 5. 课程作业与二次开发

允许：

- 阅读源码、在本地编译、改给自己用；
- 在作业或论文里引用本仓库并注明 GPL-3.0-or-later 与项目地址；
- 公开你的 fork，只要你的分发遵守 GPL。

不要：

- 去掉许可、版权或「关于」里的源码入口，再把改包当原创闭源 App 上架；
- 宣称这是某网站的官方客户端；
- 把维护者没做过的「已备案 / 已等保 / 已上架 Play」写进你的 README。

商标与网站图标归各自权利人。作业截图可以展示功能，不要暗示那些品牌在给本项目背书。

## 6. 隐私、备案和上架（同学常问）

- 应用**没有**维护者侧的用户账号云。浏览数据默认在手机上。
- 点「检查更新」会访问 GitHub 的公开接口，这会离开本机，隐私规则里写了。
- 国内应用商店上架通常要 APP 备案；本项目目前走 GitHub 侧载，**不要**在作业里写「已依法备案」除非维护者真的办完并公示编号。
- 官网若部署在境内服务器，ICP 备案是网站的事，与 GPL 无关。

更完整的处理规则见 [docs/legal/PRIVACY.md](legal/PRIVACY.md) 和 [docs/legal/TERMS.md](legal/TERMS.md)。
